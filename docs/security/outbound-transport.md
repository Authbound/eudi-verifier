# Legacy verifier outbound transport

The documented pension contract remains the legacy `/ui/presentations` flow. These source protections do not revive retired anonymous issuance routes or substitute a modern verifier runtime.

Issuer metadata/JWKS, status tokens, configured type metadata, public HTTPS wallet `jwks_uri` and policy-selected Federation configuration use address-bound public GET transport. Existing issuer trust-pattern, credential-signature and authority-selection checks remain additional requirements. Inline wallet JWKS needs no fetch. Every resolved address must be globally allowed; the same validated answer array is used by the Apache connection manager. Original hostname/TLS certificate verification is retained. Public fetches require HTTPS on port443 and forbid credentials, cookies, redirects, proxies and self-signed/hostname-validation bypass profiles.

The two documented private exceptions are separate exact contracts: POST `http://pension-backend:3010/internal/eudi-verifier/presentations/wallet-response` with its internal token, and GET `http://gateway:8080/.well-known/eudi-s2s-jwks.json`. Their named hosts must resolve entirely to private network addresses, excluding loopback/link-local/metadata ranges; raw path and method must match. Neither exception is available to public wallet/credential-controlled fetches. S2S ES256, issuer, audience and time validation remain unchanged.

AWS KMS uses the SDK-derived regional/partition endpoint, exact HTTPS root POST transport and explicit environment credentials, including an optional session token. Default instance/container metadata credential fallback and endpoint/proxy overrides are not used. The existing configured pension region/key/signing semantics remain. Additional FIPS/dual-stack/private-endpoint deployments require separate supported policy qualification.

Transport budgets: at most16 simultaneous requests; bounded DNS executor with four threads and a finite queue, two-second DNS wait, two-second connection wait, five-second socket wait and eight-second HTTP abort deadline. Bodies are limited to1MiB; compressed responses are rejected rather than decompressed. Application reads stop at the body budget plus one sentinel byte. Rejection/overflow aborts the request before Apache stream cleanup can drain additional bytes. Ktor and AWS cancellation abort their active requests. Header count/line size and request header/body budgets are bounded. This does not establish an operating-system resolver interruption guarantee or live DNS/CNI enforcement.

Local keystore/certificate loading accepts local file/classpath resources, not HTTP/FTP/JAR-over-network or remote file authorities. The pension read-only PKCS12 remains supported. Online LOTL configuration fails startup and dynamic LOTL fetch invocation fails closed until every initial/linked trusted-list and revocation download has equivalent protected transport; no partial DSS loader fallback or implicit trust is introduced.

Tests cover destination/DNS/dial binding, private/public separation, exact SDK regional root requests, malformed/oversized/compressed/redirect response rejection, abort-before-drain, actual Ktor GET/JSON POST response lifecycle and existing cryptographic/status/application regressions. Source regression acceptance is separate from exact built-image, deployment credential, DNS/CNI and live pension qualification. No shared database or provider configuration is changed by these protections.
